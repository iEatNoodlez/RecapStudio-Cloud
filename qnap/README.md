# The QNAP package

A `.qpkg` of Recap Studio Server for App Center, on a QNAP with QTS 5 or later: `x86_64` for an Intel or AMD model, `aarch64` (QDK's `arm_64`) for a 64-bit ARM one. The workflow builds one of each edition for each from the release's AppImages (`.github/workflows/build.yml`, the `qnap` job), and the README's "On a QNAP NAS" says how to install it. The x86_64 package installs and runs on a QTS 5.2 NAS (2026-11-07); the ARM one hasn't been tried on an ARM QNAP yet.

- **`build-qpkg.sh <server AppImage> [out-folder]`** puts a server AppImage (0.4.1 or later: one that brings its own glibc, since QTS 5's is too old for the app) in a package for the AppImage's architecture, read from its ELF header. An AppImage of the machine's own kind is unpacked by running it, one of the other kind with `unsquashfs` (from where its squashfs starts, after the runtime's ELF), so both build on an x86_64 machine. Needs QNAP's [QDK](https://github.com/qnap-dev/QDK) (`qbuild`). `--folder <folder>` writes QDK's build folder instead of building, for a `qbuild` elsewhere: on the NAS itself, with QDK installed there. There the folder has to sit inside QDK's own folder (`/etc/config/qdk.conf` takes QDK's path from what comes before "QDK" in the working directory): copy the folder in, `chmod 755` the service script and the AppImage (files copied over SMB can lose their execute bits), then `qbuild`; the package lands in its `build/`. `--tree <folder>` writes the package's files instead, without QDK, for testing.
- **`check-qpkg.sh <.qpkg> <AppImage>`** checks a package by its bytes, cut at the offsets its header gives: the control files, the data whole, the service script, and the AppImage the same as the one it was built from. It exits 1 otherwise.
- **`shared/RecapStudio.sh`** is the package's service script, which App Center runs (BusyBox sh). It unpacks the AppImage into the package's folder, keeps the app running, and unpacks again after the app updates itself.
- **`qpkg.cfg`, `package_routines` and `icons/`** are QDK's.
- **The header stays as `qbuild` writes it.** App Center reads the unpacking lines out of it by their exact shapes (as `qbuild --extract` does), so a line changed or added is lost: two builds with a changed data line failed on the NAS with "data file error" (`qinstall.sh`'s `tar` on an incomplete `data.tar.gz`). The line as written, `dd | cat | dd bs=1024 count=N` from a pipe, came out exact on the NAS, but off it (GNU's `dd` or BusyBox's, in Docker) it can come out short, a different length each time: `dd` counts a short read from a pipe as a whole block. So a package is checked by its bytes, not by running those lines.
